## 条件

真实运行 YOLO26n 与 YOLOE-26n，320×320，置信度 0.35，CPU 单线程，一次暖机。同一组 88 张 ADE 图片（28 既有试验集 + 60 既有留出集），输入/标注 SHA 检查通过。YOLOE 使用官方分割权重加载官方检测架构（822/822 参数项成功移植），原有 COCO80 + 10 个固定提示类；不运行分割输出，未微调模型。

命中是粗略的**图像级语义标注支持**：真实类别面积至少 1.5%；预测框已标注像素至少 10% 属于目标组，支持框合计覆盖至少 20% 该组真实区域。不是实例检测 AP，也不代表图中所有同类物体都检出。阈值在推理前固定，两模型一致。

- 手机 ADB 可访问但锁屏；未绕过锁屏，未要求用户操作。
- CLIP 首次缺少 wcwidth，补充任务目录内依赖后完整重跑；没有改变环境全局包或修改标签。
- 未启动 AVD、Gradle 或并行重型任务；PC 单推理进程，测试后已退出。

## 来源与复现

模型：[官方 YOLOE 文档](https://docs.ultralytics.com/models/yoloe)，权重与文本编码器来源/哈希见 evidence/yoloe26-quick/results.json。Ultralytics AGPL-3.0 / Enterprise；数据许可说明沿用 semantic_furniture_v06.md，图片与大权重仅本地保存。

在安装本项目 torch/ultralytics 8.4.174、OpenCV、NumPy、官方 CLIP/tokenizer 依赖的 Python 环境中，先按来源下载权重到 android/deliveries/yoloe26-quick/yoloe-26n-seg.pt，再执行：

```powershell
python android/tools/quick_yoloe_validation.py --root . --baseline <yolo26n.pt路径>
```

脚本将复用两个已有 ADE manifest 并校验全部输入哈希，首次固化类别会下载官方文本编码器。原始日志、prompt embeddings 和冻结模型在本地 android/deliveries/yoloe26-quick/。检查点 d3b3e7b 保存此前家具语义成果；本轮只提交评测代码与报告。

# Alert Behavior Diagnosis — 2026-10-11

本次只读取既有八段 UrbanEgo 开发视频的感知、风险与提醒日志，改进研究图表；未修改风险配置、评分、事件管理、提醒调度或空间音频。八段来自同一原视频，总计 120 秒，不能作为独立泛化测试集。尚无已复核 Ground Truth，以下是提醒行为统计，**不能称为误报率或安全性评价**。

## 主要结论

257 次 AlertEvent 中，232 次首次（90.27%）、25 次升级（9.73%），普通重复与感知受限均为 0。总体为 128.5 次/分钟。当前频繁提醒主要表现为大量不同事件的首次提醒，而非单事件无限升级。762 个独立事件中，530 个没有提醒、207 个一次、25 个两次；没有事件超过两次。事件 ID 必须与 video_id 联合使用。

## 可复现证据与根因边界

### 1. 新事件与身份关联是优先调查方向

120 个事件曾包含多个 track_id；13 组同视频内的**提醒当帧追踪 ID**在多个事件产生首次提醒。这是身份关联不稳定的证据，不足以证明每一组对应同一真实世界目标。

具体例子：02，track 9 在 E000006 / A000004 于 600 ms 首次提醒，score 0.488617，ACTIVE；随后 E000020 / A000010 于 1850 ms 首次提醒，score 0.589694，ACTIVE。E000006 在 1200、1300、1450 ms 进入 LOST，1250、1350 ms 恢复 ACTIVE，1550 ms 接入 track 6，2400 ms 才 RESOLVED；E000020 在 1450 ms 以 track 94 新建，1850 ms 已接入 track 9。两个生命周期重叠，不能简单归因于“超时结束后重新提醒”。现有一对一关联及几何匹配允许追踪身份在事件间迁移，具体是 ID 切换、遮挡、拥挤关联还是不同人，需逐帧人工复核。

另一个复核入口：03，track 1 的首次提醒出现在 E000003（250 ms，0.743952）、E000004（850 ms，0.800000）、E000013（3550 ms，0.722081）。以上是候选复核案例，**不自动合并事件，也不自动计为重复误报**。

### 2. 状态恢复频繁，但恢复本身不重置提醒历史

149 个事件有多次进入 ACTIVE 的记录。02 的 E000006 是直接案例：多次 LOST→ACTIVE，只有一次首次提醒；再次首次来自另一个 event_id。`decision/alerts.py` 的历史以 event_id 保存，恢复不会清空。计数说明反复恢复存在；与提醒日志联接后，不能把所有状态抖动认定为新增提醒原因。

### 3. 评分波动真实存在；等级有滞回，提醒不是每次阈值穿越

03 / E000018（track 54）于 3600 ms 首次 score 0.523241，6250 ms 升级 score 0.671575，总计两次。3650→3700 ms：0.641609→0.694908，MEDIUM→HIGH；4100→4150 ms：0.640205→0.296273，等级仍为 HIGH；5350→5400 ms：0.478793→0.445013，HIGH→MEDIUM；6200→6250 ms：0.602868→0.671575，MEDIUM→HIGH。等级多次变化，提醒仍只有一次升级。

04 / E000006 是容易误解的案例：700 ms 首次 MEDIUM / 0.461454；1150 ms score 0.692935 升为 HIGH；1700 ms 才触发升级，**当时分数已降到 0.514481，等级仍 HIGH**。这符合现有 400 ms 降级保持、0.05 降级边际及 1000 ms 升级间隔，并非图表读取错误。原始 score 与 raw_score 未做额外视觉平滑。评分图现在保留等级、质量、类别和帧号悬浮信息，明确区分实际提醒和评分点。

缺失运动特征时，评分重新归一空间与外观权重；恢复运动时权重构成改变，可影响曲线。原始 score_trace 中保留 motion_score、features、quality、reasons，便于区分此机制与目标运动。未用曲线平滑隐藏它。

### 4. 多类别、多事件贡献明显；真实物体身份仍待标注

按提醒当帧模型类别：person 113、chair 50、car 44，其余 50。05 的 chair 类别贡献 21/36 次，07 贡献 15/48 次。本批感知配置 class_ids=null，处理所有 COCO 类；风险公式没有类别对应的实际危害含义，关注区重叠和图像尺度会让许多类别进入提醒门槛。类别来自检测器，不证明现场实际有对应数量的椅子或独立障碍。

单事件最多两次，25 个并列最高贡献事件均保存于索引及完整诊断。例：01 / E000024（track 57），3150 ms 首次 0.440193，7600 ms 升级 0.697586；01 / E000059（tracks 224、247），8800 ms 首次 0.500448，10900 ms 升级 0.694154。不存在一个异常事件贡献几十次提醒的现象。

### 5. 相机运动及感知受限

现有运动特征是图像平面尺度、中心与向关注区移动，没有相机自运动估计。第一人称视频的转头和步行可能影响这些特征；目前日志不能区分相机与物体运动，**相机运动造成哪些具体提醒仍待核实**，不能把所有正尺度变化认定为真实接近或可靠碰撞预测。需要在原视频中复核所列波动片段，并用静态背景运动作诊断对照。

本批有 33 个短暂感知受限候选事件，各持续 50–100 ms，均在 500 ms 确认时间前恢复；没有 perception_limited AlertEvent。因此短暂感知状态变化存在，但不是这 257 次提醒的来源。例：03 / H000001，5550 ms CANDIDATE、5600 ms RESOLVED。762 个总事件中包含 729 个风险事件及这 33 个健康事件；Console KPI 只统计风险事件，因此 03 显示 84 而本报告总事件数为 85，两者口径不同。完整音频播放调度不是本次离线日志的一部分，未推断其行为。

## 时长与统计口径

每事件保存 start_ms、end_ms、observed_span_ms、last_seen_ms、right_censored、状态变化和提醒时刻的原始观测。686 个事件有 RESOLVED 结束，76 个在视频边界右删失；右删失事件 end_ms 使用片段结束作展示，不推断真实结束。生命周期区间包含 LOST，不等于持续可见时间。每分钟按 manifest 的实际 15 秒时长计算，而非最后一帧 14.95 秒。

## 复现与文件

在仓库根目录执行（缓存及临时文件设置在 D 盘，与现有开发环境一致）：

```powershell
$env:TEMP="$PWD/models/hybrid/tmp"; $env:TMP=$env:TEMP
$env:UV_CACHE_DIR="$PWD/models/hybrid/cache/uv"
uv run python scripts/diagnose_alert_behavior.py
```

输入：`datasets/real_world/manifests/dataset.json`，`outputs/real_world/v01/<video>/perception/tracks.jsonl`，对应 assessment 的 risk_frames/events/alerts/run_metadata。原始运行 metadata 已保留模型、配置、版本、源 tracks 哈希。

输出在新目录 `outputs/alert_behavior_diagnosis/v01/`，不覆盖原结果或 Phase 3 冻结结果：

- `video_summary.csv`：逐视频计数和频率。
- `diagnosis.json`：每事件生命周期、提醒联接、评分跳变（等级变化或相邻观测差绝对值 ≥0.15，**仅诊断筛选，不是风险阈值**）、同 track 多事件候选及输入 SHA256。
- `score_trace.jsonl`：全部原始观测、分数及特征，带 video_id、frame_index 和 timestamp_ms。
- `anomaly_index.json`：需要查看的事件、时刻和筛选标记；包含提醒事件和波动候选，**不是已确认异常真值**。

小体积快照保存在 `docs/diagnostics/alert_behavior_v01/`：统计、索引、provenance（含同 track 再次首次提醒候选）。完整原始观测不提交 Git。重跑后应检查输入哈希一致，不能以新模型结果混充本次诊断。

## 下一阶段最多三项优先改进（本次未实施）

1. **先修事件关联与身份恢复**。上述重叠事件和 13 组相同提醒当帧 track 的再次首次提醒是直接证据。调查 `decision/events.py` 的几何关联、歧义与 last_track_id 迁移，考虑谨慎的身份恢复/提醒历史继承。预期改善同实体首次提醒次数、关联碎片数；风险是误合并两个真实目标从而漏报。先独立标注案例真实身份，在完全相同 tracks 上单变量回放，衡量合并错误、首次机会检出与延迟，不能仅按提醒数选方案。
2. **再研究多目标首次提醒的预算与优先级**。90.27% 为首次，chair 等类别贡献明确；`decision/alerts.py` 当前每帧最多一次，不是跨事件时间预算。考虑可解释的跨事件仲裁及类别/场景适用性，而非直接屏蔽椅子。预期改善全局提醒密度与独立机会重复提醒；可能压制同时出现的重要目标或增大等待时间。保持 tracks 相同，固定预算候选，使用复核后的机会窗口评价 recall、misses、latency，并单列 HIGH 提醒及多目标场景。
3. **最后研究评分瞬态与升级确认的时间一致性**。04 的迟到升级和 03 的等级波动说明需要检查“当前分数、滞回等级、延迟升级”关系。调查 `risk/scoring.py` 与 `decision/alerts.py`，候选为升级证据持续确认、运动可用性切换解释，之后才考虑自运动诊断。预期改善短暂峰值后的迟到升级及曲线解释性；持续确认会增加延迟、漏掉短时风险。相同 tracks 单变量回放，比较升级机会检出与延迟、提醒时分数/等级一致性，仍保留所有原始曲线。

所有实验需先完成独立标注、保留 baseline 配置与输入哈希，输出新 run_id，不改冻结实验。**提醒减少不等于安全性提高**。

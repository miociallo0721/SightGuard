# 智能眼镜展示网页

启动：`uv run sightguard ui --port 7860 --open-browser`。
旧研究控制台：`uv run sightguard ui --research --port 7861`。
两种界面仅绑定 127.0.0.1，不创建公网分享。展示网页不自动打开摄像头。

## 产品与交互

- 浅色产品首屏、黑色眼镜外观参考、摄像头/喇叭/单侧震动马达介绍。
- 深色视频体验台：上传 MP4（最多 500 MiB），开始识别，等待异步处理完成。
- 视频、目标类别/置信度、方向建议、语音文字及马达节奏随同一播放帧更新。
- 浏览器语音由用户点击试听；浏览器缺少语音引擎时显示错误，不自动连续播报。
- 网页不驱动真实震动马达或眼镜喇叭，硬件状态始终明确为未连接。
- 示例入口读取已有分析目录；优先 tracking_verified。没有本地示例时提示上传。
- 模型配置 `configs/showcase.yaml` 检测全部内置类别；不修改研究默认类别设置。
- 无测距模块，不显示推断米数。未训练类别、盲区、遮挡等可能无法检测。
- 已有研究控制台 API 和研究记录保留，主 CLI `ui` 默认进入新的展示网页。

## 方向演示规则 1.0

用户本次明确要求展示前进、左转与右转的决策。新增 `decision/demo_guidance.py`
专用于课堂/科创演示，不提供经过验证的导航或主动绕障，未改写原风险状态机。
输入为可独立重放的 FrameRecord，不依赖 YOLO、PyTorch 或网页对象。

阈值统一存于 `configs/demo_guidance.yaml`，版本 1.0：

1. 画面按 x=0.35/0.65 分成左、中、右区域，目标坐标裁切到画面边界。
2. 关注底边至少达到画面高度 0.55、面积至少占 0.015 的目标。
3. 感知失败、没有有效目标时输出 unknown（暂不判断），不将空检测当作安全。
4. 中央目标面积至少占 0.30 时停止；中央存在目标且两侧占用差不足时也停止。
5. 中央没有触发关注规则的框时给出 forward 演示建议；有中央目标时比较两侧
   检测框相交面积，差大于 0.035 时指向占用较少的一侧。
6. 前进或转向需至少两次观测、350ms 连续视频时间确认；停止与未知即时生效。
   感知失败重置确认，每段视频创建独立状态。时间倒退报错。

检测框较少不证明区域可通行，画面占用不能解释为真实距离/碰撞概率。
当前展示前进/左右转时仍说明未验证可通行。规则可能受框重叠、漏检或摄像机运动影响。

单侧马达示意：前进短震一次、左转短震两次、右转短震三次、停止长震一次；
短震150ms、间隔150ms、长震600ms，unknown 无编码。尚未形成硬件协议或用户验证结果。

## 输出和复现

上传视频继续调用 AnalysisJobs → analyze_video → assess_tracks。每次建立新输出目录，
保留原有输入、模型哈希、软件版本、配置和失败信息。网页任务同时写入
`outputs/console/showcase-<id>.json`，包含 schema_version、感知帧、建议、原视频时间戳、
播放时间、规则配置与源码哈希，以及明确的硬件未连接状态。

标注预览为恒定帧率（CFR），按 `floor(currentTime * fps)` 映射实际播放帧，
不能用浏览器播放时间替代原视频的 VFR 时间戳。下载结果同时保留两种时间。

一次只允许一个模型任务。上传失败释放占用；失败任务不返回成功结果；页面错误后
清空旧结果，避免将上一段视频的建议误当作新结果。服务重启后内存任务 ID 失效，
磁盘分析记录保留。结果 JSON 按完整视频加载，长视频需关注内存与磁盘。

图片为用户提供的设计参考图裁切，来源和生成方式见 `ui/web/assets/README.md`。
品牌保留仓库名 SightGuard，团队介绍只使用“高中科创团队”，没有编造学校或联系方式。

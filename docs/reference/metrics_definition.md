# Phase 3 指标定义

## 评价对象与匹配单位

评价单位是人工标注的提醒机会，而不是模型事件 ID、跟踪 ID 或逐帧检测。每个有效机会有唯一 `opportunity_id`，关联独立人工 `event_id`，并具有 `kind`、时间窗口及最低严重程度。策略提醒与机会候选边要求：同一视频、语义类别兼容、提醒严重程度不低于机会下限、提醒类型兼容、提醒时间落在窗口内，并且目标区域条件满足。

时间窗口两端均包含：

`window_start_ms <= alert.timestamp_ms <= deadline_ms`

`first` 只匹配 `initial`，`escalation` 只匹配 `escalation`；基线 `trigger` 与 `repeat` 可匹配任一满足其他条件、尚未被占用的机会。`perception_limited` 是诊断提醒，不与场景机会匹配。评估器不使用提醒上的算法 `event_id` 或 `source_track_ids` 建立 Ground Truth 身份。

匹配器对一个视频内所有提醒和机会执行确定性的最大基数二分匹配。一条提醒最多对应一个机会，一个机会最多接受一条提醒。最大基数保证不因局部贪心选择而损失可实现的匹配数；输入排序和增广路径遍历顺序固定，以保证相同输入可复现。空间标注区域生效时，提醒框与人工目标框的 IoU 必须达到预设下限；同类别事件重叠但无法通过区域分开的提醒按歧义处理，不强行归属。匹配策略对 A/B/C 相同。

未匹配提醒若唯一对应到一个已匹配、仍在标注区间内的同一 Ground Truth 事件，则记为 `duplicate`；否则记为 `false_positive`（不支持、时机/严重程度/类别不合、身份歧义等）。重复提醒是 FP 的子集。`ignored` 表示提醒位于视频外或排除时段；`perception_limited` 只作诊断统计。漏掉的机会另写 `missed_opportunity`，不会被空检测或没有模型事件 ID 消除。

## 排除时间和有效时长

将标注的显式排除区间、不确定/排除事件区间合并；任何与合并并集有正时长交集的确认事件整段删失，并把其事件范围加入排除集合，迭代至稳定。仅边界相接不触发事件删失。排除区间按 `[start_ms, end_ms)` 判断提醒是否位于其中，首尾相接的区间合并。被排除事件的机会不进入分母；区间中的提醒写为 `ignored`，不计入 TP、FP 或有效提醒频率。

对视频集合 \(V\)，第 \(v\) 段视频时长为 \(D_v\)，排除区间并集的长度为 \(X_v\)：

\[
T_{\mathrm{effective}}=\sum_{v\in V}(D_v-X_v)
\]

重复或重叠排除区间只扣除并集长度一次。真实输入缺失、无效标注、源感知失败或策略失败属于失败/不可评价状态，不作为零风险时长，也不应把该视频的空提醒结果并入成功结果。

## 计数和核心指标

令 \(O\) 为保留的、所有已确认事件上的有效机会集合；\(M\subseteq O\) 是一对一匹配成功的机会集合。令 \(G_{\mathrm{imp}}\) 为保留的、严重程度属于配置重要等级（默认 `MEDIUM`、`HIGH`）的事件集合。事件仅当其 `initial` 机会成功匹配时视为检出；只匹配到升级机会不算首次事件检出。

### 有效机会计数

- **TP**：\(|M|\)，匹配成功的机会数。
- **FN**：\(|O|-|M|\)，未匹配的机会数。
- **重复提醒数**：`duplicate` 状态数。
- **其他无支持提醒数**：`false_positive` 中非重复的提醒数。
- **FP**：重复提醒数 + 其他无支持提醒数。重复提醒已包含在 FP 内，不再额外加到 FP。

机会召回率为：

\[
R_{\mathrm{opportunity}}=\frac{TP}{|O|}
\]

机会分母包含所有保留确认事件上的机会；事件严重程度是否列为“重要”不改变此机会指标。

### 重要风险事件召回率

令 \(d_e=1\) 表示重要事件 \(e\) 的首次 `initial` 机会匹配成功，否则为 0：

\[
R_{\mathrm{event}}=\frac{\sum_{e\in G_{\mathrm{imp}}}d_e}{|G_{\mathrm{imp}}|}
\]

分母是保留确认的中/高重要事件。漏检仍计入分母并计为事件 FN；即使该事件在感知 JSONL 中完全没有检测，也不能删除。被预先排除或保守删失的事件不属于可评价事件，须另行报告排除时长与事件数。

### 无效提醒和重复提醒

无效提醒频率按有效视频小时计算：

\[
F_{\mathrm{invalid/hour}}=\frac{FP}{T_{\mathrm{effective}}/3{,}600{,}000}
\]

重复提醒率按当前实现定义为重复场景提醒数占有效评价时段内全部场景提醒数的比例：

\[
R_{\mathrm{duplicate}}=\frac{N_{\mathrm{duplicate}}}{N_{\mathrm{scene}}}
\]

因此重复提醒既反映在无效提醒频率的 FP 分子中，也单独报告其计数和比例；不能把重复提醒误报成额外真阳性。`perception_limited` 不进入场景 FP 或重复率分母，但会计入总提醒频率。

### 首次响应延迟

对每个成功匹配首次机会的重要事件，延迟定义为：

\[
L_e=t_{\mathrm{first\ alert},e}-t_{\mathrm{window\ start},e}
\]

统计均值只对成功匹配首次机会的事件计算；漏检事件没有可定义的响应延迟，不能被当作零延迟，也不能从报告中隐藏。报告响应延迟时必须同时给出重要事件总数、成功首次匹配数和漏检数。

### 按时事件提醒率

按时事件提醒率以所有重要事件为分母，分子是首次机会在标注截止时间前被匹配的事件：

\[
R_{\mathrm{on\ time}}=\frac{\#\{e\in G_{\mathrm{imp}}:d_e=1\land t_e\leq deadline_e\}}{|G_{\mathrm{imp}}|}
\]

由于本评价器只在包含截止时刻的有效机会窗口内建立匹配边，目前按时事件提醒率与事件召回率相同。窗口外的早到或迟到提醒不能匹配，并按未支持提醒/漏机会等规则记账。

### 总提醒频率

有效评价时段内的总提醒数包括场景提醒和 `perception_limited` 诊断提醒，不含 `ignored` 提醒：

\[
F_{\mathrm{all/min}}=\frac{N_{\mathrm{valid\ alerts}}}{T_{\mathrm{effective}}/60{,}000}
\]

报告中应同时列出 `scene_alerts`、`perception_alerts`、`ignored_alerts` 和总数，以免诊断提示被误读成风险事件误报。

## 汇总、空分母与统计单位

所有比率在总体汇总时使用合并后的分子和分母计算，不能对逐视频比率作无权平均。总体响应延迟均值由所有成功首次匹配的重要事件延迟合并计算；同时保留逐视频结果，以显示视频间差异。

分母为零时，对应比率或均值写为 JSON `null` / CSV 空单元格，而不是 0、无穷大或伪造值：重要事件数为零时事件召回/按时率未定义；机会数为零时机会召回未定义；有效时长为零时每小时/每分钟频率未定义；无场景提醒时重复率未定义；没有成功首次匹配时延迟均值未定义。有效的空风险视频仍然是有效负样本：若无场景提醒，其 FP 为 0、有效时长大于 0、总提醒频率为 0；这与输入缺失、空 manifest、draft 标签或策略失败严格区分。

若样本量足够，可按独立 `source_group_id` 或视频为单位进行 Bootstrap；不得把视频连续帧当成独立样本。来源组数量不足时不报告置信区间或显著性结论，明确写明样本限制。只有输入中包含可靠分段执行日志时，才可报告感知/风险/决策处理延迟；benchmark 自身离线运行墙钟耗时不是设备端响应延迟。

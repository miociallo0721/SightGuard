## 一、交付结论

SightGuard 已形成从本地视频感知、离线风险重放、事件级提醒到独立标注对照评价及研究控制台的工程链路。
本次在既有 Phase 1–3 基础上完成 Phase 4，实现四个可操作的 Gradio 页面，并完成自动化测试、
本地模型集成验证、HTTP 操作验证、浏览器基本交互检查和 Python 包构建。

交付状态为**研究原型功能实现与本机工程验证完成**。现有证据支持代码、数据流与实验展示流程的可运行性；
尚不支持真实道路预警有效性、视障用户使用效果或安全性结论。本报告记录实际完成事项，不代替用户最终验收。

## 二、项目目标与阶段范围

项目研究连续视频中的风险事件筛选：在保留重要风险检出能力的前提下，减少无效和重复提醒。
系统定位为盲杖、导盲犬等工具的补充；画面空间、尺度和运动特征是视觉代理线索，
不能解释为真实距离、真实速度、碰撞概率或可靠碰撞预测。

截至本次交付，工程包含：

- **Phase 1：视觉感知。** 本地 MP4 输入、YOLO26n 检测、BoT-SORT 跟踪、逐帧感知 JSONL、标注视频和运行元数据。
- **Phase 2：风险与事件。** 可解释特征和风险评分、事件生命周期、首次/升级/可选重复提醒及感知受限提示。
- **Phase 3：对照实验。** 独立 Ground Truth Schema、A/B/C 策略重放、机会匹配、指标、数据校验和协议冻结。
- **Phase 4：研究控制台。** 结果浏览、视频分析入口、时间定位、策略时间线、实验统计与只读数据集校验。

本次没有开发移动端、完整导航、路径规划、主动绕障、提醒音频或新视觉模型。
没有引入云端视觉 API、LLM、React、Electron 或数据库服务。

## 三、本次完成的功能

### 1. 视觉分析页面

支持上传本地 MP4 或选择已有运行。主动发起分析时，创建唯一运行目录，调用既有视频 Pipeline，
再对生成的感知记录执行 Phase 2 重放；进度来自实际处理帧数及视频时间。

页面展示标注视频、检测数量、视频内追踪 ID 数、风险事件数量、首次/升级提醒及感知受限提示数量，
并呈现风险曲线、帧级特征、事件状态、提醒原因与完整生命周期记录。
这些数量明确作为运行统计，不作为正确识别率。

时间控件按 JSONL 时间戳选择请求时间之前最近的帧，显示实际帧号、时间和关键帧；
事件定位与保存的生命周期记录对应。播放器与时间控件独立操作，不声明双向播放同步。
分析结果可导出为独立 ZIP 副本。

### 2. 策略对比页面

读取已完成 benchmark，按视频、A/B/C 和人工/模型事件筛选，共用视频时间轴。
时间线区分首次、升级、基础触发、重复和感知受限提醒，并显示人工提醒窗口、匹配状态与遗漏机会。
模型事件 ID 和独立标注 ID 分离；不同策略中同名事件不会被错误合并。

事件召回与提醒机会召回分别展示。页面提供基于已有感知 JSONL 的策略行为预览，
允许选择现有 YAML 配置；该入口不加载 Ground Truth、不生成 TP/FP/FN 或召回结论。

### 3. 实验分析页面

直接读取 Phase 3 保存的 `metrics.json` 和分视频、场景、严重程度及错误案例 CSV，
提供指标图、原值表与错误筛选。UI 不另行实现指标算法，也不因筛选视频改写整次实验汇总。

Synthetic、Real 和 unknown 来源明确区分；未定义数值展示为 `N/A`。
缺少完整且可验证真值时，页面隐藏准确性指标与错误分类，原始历史文件保持不变。

### 4. 数据集管理页面

只读浏览 manifest 的视频、划分、来源组、数据类型、标注审核状态和文件状态，
调用既有 Phase 3 校验器检查 schema、来源及输入证据。
页面不编辑标注、改变划分、训练模型或重新冻结实验协议。

## 六、存量实验结果及解释边界

控制台展示的是既有 Phase 3 合成测试结果，本次 UI 开发没有重新生成这些指标。
`outputs/phase3_final/metrics.json` 对应 4 个测试视频、13 秒有效时长、3 个重要事件和 4 个提醒机会。

- 策略 A：TP 2、FP 34、FN 2，36 次提醒，其中重复 22 次；事件召回 2/3，机会召回 2/4。
- 策略 B：TP 2、FP 2、FN 2，4 次提醒，其中重复 1 次；事件召回 2/3，机会召回 2/4。
- 策略 C：TP 3、FP 1、FN 1，4 次提醒，无重复；事件召回 2/3，机会召回 3/4。

TP/FN 按独立提醒机会计数，重复提醒已包含在 FP 中，不能再次相加。
在这组脚本化合成输入中，C 保留了额外的升级机会并减少重复，三种策略的事件召回仍相同；
完全漏检事件仍被保留为遗漏，不能由事件决策弥补不存在的感知证据。
这些数值只支持流程与实现检查，不支持真实道路性能宣传。

## 七、安装、启动与复核

进入项目目录，在 Python 3.12 和 uv 环境中执行：

```powershell
uv sync --locked
uv run sightguard ui --port 7860
```

浏览器访问 `http://127.0.0.1:7860`。只绑定本机回环地址，不提供公开分享链接；
构建和浏览已有页面不加载模型，主动视频分析需要先准备 `models/` 内权重。
首次安装依赖需具备包源或本地缓存，权重与大视频不随源码默认交付。

复核工程检查：

```powershell
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
$env:SIGHTGUARD_TEST_MODEL = (Resolve-Path models/yolo26n.pt).Path
uv run pytest -q
Remove-Item Env:SIGHTGUARD_TEST_MODEL
uv build
```

HTTP 验证需先启动控制台并准备相应分析及 benchmark；脚本支持指定运行目录，报告拒绝覆盖。
新电脑不能把本机未提交的夹具视频、权重和 `outputs/` 当作自带资源。
完整操作见[项目 README](../README.md)。

## 八、已知限制与后续验收事项

1. 缺少足够的独立真实动态街景数据及真实使用者验证。下一轮研究应优先确认采集、独立审核、
   来源分组和 development/test 隔离方案，再开展真实视频对照评价。
2. 当前只验证本机 Chromium 及短视频。Firefox/Safari、触屏、完整键盘遍历、长视频和大型结果集
   仍需人工验证；不声称已完成跨平台和压力验收。
3. 上传限 500 MiB，模型任务串行执行；整份结果加载、首次 H.264 转码和缓存增长可能影响资源占用。
   后续需明确 RAM、磁盘预算和缓存维护方式。
4. 标注视频为恒定 FPS、无音频副本，播放器位置不能替代 JSONL 时间。没有双向播放同步或在线实时预警。
5. 新增 benchmark/manifest 后需重启控制台刷新相应目录列表。数据集页面不提供标注编辑或协作管理。
6. 算法、依赖、配置或数据变化后，应按 Phase 3 流程建立新的实验版本；不得改写历史冻结证据来掩盖调参。
7. ONNX、Core ML 和 iOS 尚未实现；未来部署选择需依据真实视频效果、延迟、功耗和模型兼容性测量。

本次交付停止于 Phase 4。后续工作的优先事项是补齐真实评价证据和使用验证，工程性能优化及移动端部署
需另行确定范围，不能据本次测试结果直接推定已经具备道路安全应用条件。

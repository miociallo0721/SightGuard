# 独立视频事件标注规范

## 标注目的

本规范用于建立独立于检测器、跟踪器及提醒策略的人工事件真值。标注依据原始视频中可见的信息，描述“画面是否出现了值得提醒的风险线索”和“提醒在什么时候仍有帮助”，不判断真实距离、实际速度或碰撞概率。不得为了制造样本而在现实道路上主动制造危险情况。

## 盲化和记录流程

1. 标注者只查看原始视频及其视频时间，不查看 `tracks.jsonl`、检测框、跟踪 ID、模型分数、策略提醒或算法事件记录。标注窗口、类别和严重程度必须在算法结果揭示前确定。
2. 先确认视频完整性、可见性、视频时长和来源，再逐段标记事件和无法可靠判断的片段。使用视频时间戳，单位为毫秒；不得用电脑墙钟或推理耗时替代。
3. 按固定的项目分工进行复核。对事件是否重要、事件身份、起止点或提醒窗口存在分歧时，先保留原始意见，再由复核者裁定；无法裁定时标为 `uncertain`，不得为了得到完整指标而强行改成正例或负例。
4. 人工复核完成后，将视频标注文档设为 `reviewed`，来源为真实视频时使用 `label_source="human_raw_video"`，并记录负责标注者。真实视频标注应保存视频 SHA-256 与文件出处；合成场景应使用 `label_source="synthetic_scenario"`，不得伪装成人工真实街景。
5. test 标注应由独立、盲化的流程完成，并在查看 test 策略结果前固定。任何修订都应另存版本、记录理由，并重新冻结评估协议；不可根据指标表现修改 test 标签。

当前 schema 记录标注者、审核状态、来源和文件哈希，但代码无法证明标注者是否看过算法输出、是否遵循盲化或是否有利益冲突。请另存标注与复核日志。哈希是完整性证据，不是独立性证明。

## 什么算风险事件

事件是同一个可见目标或连续场景状况，在一段时间内持续提供风险相关线索，并至少存在一个值得提醒的时机。依据可见画面和预先约定的关注范围，不依据待测算法是否检测到目标。

- **重要风险线索：** 目标明显位于前方可通行区域，或正在进入、横穿或阻断该区域；静态物体占据合理的前行空间；目标的画面变化、位置和持续时间足以让用户需要注意、减速或停步。仅按画面证据判断，不把它解释成物理距离或碰撞预测。
- **一般不需要提醒：** 目标清楚地位于路线之外且远离关注区域；横向经过但没有进入或接近前方通行区域；目标朝远离画面关注区域的方向离开；背景物体、海报、屏幕内容或明显隔离在不可达区域的物体。
- **横向经过：** 只有当目标轨迹或连续画面显示其进入前方通行区域、与预期前行区域相交或造成需要注意的阻挡时，才标为风险事件。目标只是在边缘横穿、没有影响前行区域时不标重要风险。若相机转动使相对方向无法判断，标记不确定或排除相应区间。
- **静止障碍：** 若物体处于可通行的前方区域且具有足以影响前行的视觉规模、位置或持续性，可以标注；不要求物体移动。不要从普通视频推测精确距离或宣称即将碰撞。

事件严重程度使用 `LOW`、`MEDIUM`、`HIGH`：

- `LOW`：有一定相关性，但按本项目预先规则不属于重要风险；只在研究需要保留低等级事件时标注。
- `MEDIUM`：可见线索足以支持提醒或引起明显注意，存在合理的前方通行干扰。
- `HIGH`：可见目标对前方通行区域形成强烈、紧迫的干扰，需要立即注意、减速或停步。

严重程度是标注等级，不是碰撞概率。benchmark 默认把 `MEDIUM` 和 `HIGH` 计入重要事件；如需更改，应只在 development 阶段预先设置，并冻结到协议中。

## 事件边界、遮挡和重复机会

`start_ms` 取最早出现足够视觉证据、可以合理启动提醒的时间，而不是目标第一次出现在任意画面的时间；`end_ms` 取目标离开前方关注范围、风险线索明确消失或视频观察结束的时间。事件和目标区域的起止值记录首次/末次相关画面时间；当前评价器在判断事件和区域是否有效时将两个边界都视为有效。排除时段另按半开区间处理，二者不能混为一谈。视频截止时事件仍在持续，应保留观察到的边界并在 notes 中说明截尾，不得虚构目标消失时间。

短暂遮挡时，若遮挡前后的类别、出现位置、运动方向及场景连续性支持同一目标，可继续标为同一个事件；建议把不超过 1 秒作为短遮挡的初始操作阈值，并在项目开始前固定。超过该阈值、目标重新出现的位置/运动明显不连续，或身份无法可靠判断时，应拆分事件或标为不确定。这个判断由原始画面完成，不使用跟踪器 ID。

同一个连续风险过程通常只有一个首次提醒机会。只有出现独立且可见的风险变化、严重程度确实提高，并且再次提醒会有实际帮助时，才增加 `escalation` 机会。目标离开风险区域后又重新进入，形成新的独立遭遇时，标为新事件；目标仍持续存在但每帧重复出现，不构成多个提醒机会。升级机会必须晚于首次窗口起点，并要求更高的最低严重程度。不是每个事件都需要升级机会。

每个 `confirmed` 事件必须有且只有一个 `initial` 机会；升级机会可以没有，也可以有多个。机会窗口由人工独立确定：`window_start_ms` 是最早仍然有帮助的提醒时间，`deadline_ms` 是最晚仍可视为有效的时刻，两端均包含。`minimum_severity` 表示提醒至少要达到的程度。起点和截止点必须位于事件区间内；截止点必须早于视频总时长，因为评价器不接受时间戳大于或等于视频时长的提醒。不可根据 A/B/C 的提醒时间或风险分数倒推窗口。

示例：人工看到目标开始进入前方通道，可能在 `[1200, 2200] ms` 内提醒，最低 `MEDIUM`；若目标后来明显进入更紧迫状态，可独立增加更晚的 `escalation` 窗口，最低 `HIGH`。该例仅演示字段含义，不是实际标注或建议阈值。

## 不确定事件和排除时段

`annotation_status` 的含义：

- `confirmed`：事件身份、风险意义和首次机会可按规范可靠确定。
- `uncertain`：存在潜在风险，但类别、目标身份、严重程度或有效时机无法可靠判断。保留原始记录和原因，不作为负例，也不进入可匹配机会分母。
- `excluded`：画面中的状况不适用于本次预先定义的评价，或其风险与边界不能形成可评价样本。它不是“没有风险”的同义词。

`uncertain` 和 `excluded` 事件不应填写提醒机会；即使文件中存在机会，它们也会随事件一起排除，不参与匹配。

标注为 `uncertain` 或 `excluded` 的事件时间范围都会成为评价排除时段。也可通过 `excluded_intervals` 标记相机被遮挡、画面冻结、过暗、严重模糊、剧烈转向或其它导致整段画面不可可靠评判的时间范围，并填写具体原因。排除范围与事件有正时长交集时，评价器按保守规则删失整个确认事件；仅边界接触不触发删失。被删失事件的完整时段继续扩展排除并集，因此可能连带删失其他重叠事件。标注者应尽量把排除段限定在确实无法判定的范围，并检查这种扩展结果。

正常画面且没有重要风险时，不创建 `uncertain` 事件，而应提交 `reviewed` 且 `events` 为空的负样本。`draft` 文档不是负样本，不能参加 benchmark。

## 相机运动、画质和目标位置

- 相机转向、抖动或拍摄者移动可能造成背景与目标的相对运动；不能仅凭框变大或画面移动推断目标接近。使用背景参照、目标在前方关注区的位置及连续可见的方向线索。如果这些线索不足，标为不确定或排除区间。
- 画面低分辨率、曝光不足、镜头遮挡、压缩伪影或快速运动模糊若影响事件判断，应记录准确时间段和原因。不要将不可见解释为无风险。
- 同一时段多个同类别目标重叠时，给每个目标添加人工标注的 `target_regions`（归一化 `xyxy` 框及生效时间），以便评价器区分事件。区域取自原始视频，不参考模型框；若不能区分目标，应标不确定，而不是复用跟踪 ID。
- `class_ids` 使用项目固定的语义类别映射；`event_type` 使用简洁、稳定的场景类别名称。一个事件含多个合理类别时明确列出，避免每次实验改变映射。

## 完成前检查

保存前确认：视频、标注与 manifest 的 `video_id`、时长、来源哈希一致；所有时间值为毫秒且位于视频范围内；事件 ID 和机会 ID 在视频内唯一；每个确认事件恰有一个首次机会；升级窗口晚于首次且最低严重程度更高；窗口在事件范围内；重叠的同类别确认事件提供足以区分对象的目标区域；不确定/排除时间有原因；审核状态为 `reviewed`。`validate-labels` 的通过只说明结构、来源完整性和时间覆盖符合校验规则，不证明语义标注正确或标注过程独立。

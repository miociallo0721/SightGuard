# 发布与回退

## 准备交付

1. 在独立分支确认版本、功能开关和模型清单；保留此前 APK、源码提交与 SHA256。
2. 完成与改动对应的检查。区分规则测试、真实模型、模拟器和实体设备，不把构建成功写成全部验收通过。
3. 使用明确的资产清单构建 release 包，检查 manifest 权限、包名、版本码和签名。
4. 在已授权设备上覆盖安装并检查启动、停止、语音和本轮变化。保留失败与未完成项。
5. 保存版本说明、APK 哈希和回退指引；通过 PR 审阅，不自动覆盖 master。

当前 APK 使用开发签名，仓库尚未配置生产签名或商店发布。自有原创源码采用 [AGPL-3.0-only](../../LICENSE)，第三方内容保留原许可。正式对外发行前，维护者仍需确认签名管理、模型授权及组合分发兼容性；添加源码许可证不消除 SegFormer 等上游限制。

分发二进制时，按适用许可提供对应源码、必要构建材料、许可证与版权声明，并记录 APK 对应的源码提交和模型版本。只给出仓库首页链接不等于已经满足全部对应源码义务。Android assets 中附带本项目的 AGPL 原文与范围说明；这不替代其他组件的许可要求。

## 交付目录

本地交付建议包含：

```text
deliveries/<版本>/
  SightGuard-<版本>.apk
  SHA256SUMS.txt
  release-notes.md
  validation-summary.json
  rollback.md
```

APK、原始设备日志和私人截图不提交 Git。只提交经过整理的版本说明和必要证据；发布安装资产是单独的发行操作。

Windows 哈希检查：`Get-FileHash <APK路径> -Algorithm SHA256`。

## 保留数据回退

Android 可能拒绝低版本覆盖高版本。同签名的基线源码可重新构建为不低于当前版本码的回退包，再使用 `adb install -r`。不要默认卸载应用、清除数据或承诺 `-d` 在所有设备可用。

研究开关关闭不一定等于完整版本回退。恢复后应再次确认模型清单、功能配置和语音策略。
